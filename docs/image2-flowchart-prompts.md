# Image2 流程图提示词记录

本文件记录当前三张流程图的 image2 生成思路，便于后续维护。图片已经保存到 `docs/assets/`，README 和概述文档直接引用这些 PNG。

## 共同风格

```text
红白中文工程信息图风格：
米白纸感背景、深红主色、黑色粗标题、圆角白色信息块、柔和阴影、红色编号徽章、红色闭环箭头、简洁线性图标。
画面要像专业中文信息图，而不是普通技术流程图。
禁止赌博、下注、收益、竞猜和平台水印。
```


## 复杂全生命周期图

输出文件：`docs/assets/complex-full-workflow.png`

核心文案：

```text
标题：世界杯预测模型全生命周期
副标题：资料、审计、计算、报告、复盘、修正，一次跑通

01 收集资料：赛程、球队、排名、状态、伤停、赛果
02 整理快照：统一字段，记录来源和版本
03 输入审计：检查缺失、重复、混用和异常
04 强度评分：把实力差、状态差转成预期进球
05 概率计算：生成比分矩阵和胜平负概率
06 报告输出：写成中文分析文章和候选比分
07 赛后记录：记录实际比分、命中、误差
08 修正下一版：新事实写入快照，重新审计计算

底部：旧预测不修改，新信息进入下一版
```

## 分层修正机制图

输出文件：`docs/assets/harness-layered-correction.png`

核心文案：

```text
标题：模型复盘与修正机制
副标题：不是改旧答案，而是把新事实写进下一版

01 资料层：赛程、排名、伤停、赛果
02 快照层：统一字段，保留版本号
03 审计层：检查来源、缺失、异常
04 模型层：重新计算预期进球和概率
05 报告层：把结果写成人能读懂的分析
06 复盘层：记录命中、误差、校准分
07 修正层：形成下一版修正建议

中心：审计 → 计算 → 记录 → 修正
底部：每一次变化，都能解释为什么
```

## 第二版多 Agent 工作流图

输出文件：`docs/assets/multi-agent-v2-workflow.png`

核心文案：

```text
标题：世界杯预测 Skill 第二版
副标题：五个子 Agent 分工，总控串联完整流程

00 总控 Agent：接收用户请求，检查每一步产物
01 收集 Agent：赛程、排名、伤停、首发、天气、新闻
02 审计 Agent：来源可信度、时间一致性、真假核对
03 预测 Agent：xG、比分矩阵、胜平负概率
04 报告 Agent：专业中文分析、来源说明、风险声明
05 修正 Agent：赛后命中、Brier score、权重建议
06 人工确认：修正建议确认后进入下一版

底部：收集不预测，审计不改概率，修正不自动改权重
```

## 复核要点

每次重新生成后必须检查：

- 中文是否有错字、漏字或多字。
- 箭头是否能看出闭环。
- 是否出现下注、盘口、收益、稳赚等风险词。
- 是否保留“概率不等于结果”的风险边界。
- 上传 GitHub 后，README 相对路径是否仍能正常显示图片。
