# 模型方法论

这份文档解释小蜗版世界杯预测模型如何把资料转换成 90 分钟胜平负概率、候选比分和复盘指标。它面向两类读者：非技术读者可以看懂概率从哪里来，技术读者可以看到公式、数据结构和限制。

## 非技术版

模型不是直接猜“几比几”。它会先问：两队各自大概能创造多少进球？这就是预期进球。然后模型把所有比分都列出来，给每个比分一个概率。最后：

- 主队赢的比分全部相加，就是主胜概率。
- 平局比分全部相加，就是平局概率。
- 客队赢的比分全部相加，就是客胜概率。

所以胜率不是凭感觉写出来的，而是从比分矩阵一步步汇总出来的。

可以把它理解成一张“比分账本”：

- `1-0`、`2-0`、`2-1` 这些都算主队赢。
- `0-0`、`1-1`、`2-2` 这些都算平局。
- `0-1`、`1-2`、`0-2` 这些都算客队赢。

模型不是只挑一个比分，而是先给每个比分分配权重，再把同类结果加总。

## 技术版

核心路径：

```text
球队强度 + 状态 + 攻防 + 赛地 + 结构化修正
-> 双方 xG
-> 泊松比分矩阵
-> Dixon-Coles 低比分修正
-> 胜平负概率
-> 置信度和冷门风险
```

当前公式摘要：

```text
homeXG = 1.32 * homeAttack * awayDefense
       + ratingDelta * 0.38
       + formDelta * 0.15
       + hostBoost

awayXG = 1.32 * awayAttack * homeDefense
       - ratingDelta * 0.38
       - formDelta * 0.15
       + hostBoost
```

其中：

- `ratingDelta = (homeRating - awayRating) / 400`
- `formDelta = (homeForm - awayForm) / 100`
- `defenseStrength` 是对手 xG 的乘数，越低代表防守越稳。

## 输入变量

| 字段 | 含义 | 进入模型的方式 |
| --- | --- | --- |
| `ratingValue` | 首选综合强度 | 直接进入评分差 |
| `eloRating` | Elo 强度 | `ratingValue` 缺失时使用 |
| `fifaRank` | FIFA 排名 | 前两者缺失时做兜底换算 |
| `formScore` | 近期状态 | 转成 `formDelta` |
| `attackStrength` | 进攻强度 | 乘入本队 xG |
| `defenseStrength` | 防守/失球压力 | 乘入对手 xG |
| `venueCountryCode` | 赛地国家 | 匹配球队国家时给轻微 hostBoost |
| `contextAdjustments` | 结构化修正 | 审计通过后影响状态或攻防乘数 |

## 评分兜底逻辑

模型优先使用 `ratingValue`，因为它可以承载用户自己的综合评分；没有时使用 `eloRating`；再没有时使用 FIFA 排名兜底：

```text
rating = clamp(2050 - (fifaRank - 1) * 8, 1300, 2050)
```

这让样本可以在数据不完整时继续跑，但报告必须说明“使用了排名兜底”，不能把它包装成完整强度数据。

## 比分矩阵

假设主队 xG 为 `λ_home`，客队 xG 为 `λ_away`。模型枚举 0 到 7 球：

```text
P(homeGoals = h) = Poisson(λ_home, h)
P(awayGoals = a) = Poisson(λ_away, a)
P(score = h-a) = P(h) × P(a)
```

足球低比分之间不是完全独立，所以模型对 `0-0`、`1-0`、`0-1`、`1-1` 做 Dixon-Coles 修正。它的作用很小，但能让低比分矩阵更符合足球比赛的实际分布。

## 胜平负汇总

```text
homeWin90Prob = Σ P(h-a), where h > a
draw90Prob    = Σ P(h-a), where h = a
awayWin90Prob = Σ P(h-a), where h < a
```

`topScorelines` 是比分矩阵里概率最高的几个比分。注意：头号比分经常只有 10% 左右，因为足球比分天然分散，不能把头号比分当成“确定答案”。

## 置信度和冷门风险

置信度来自最高结果概率的集中程度：

- 最高概率足够高：`high`
- 中等集中：`medium`
- 三种结果接近：`low`

冷门风险与置信度相关，但不是同一个概念。比如强队胜率 54% 仍可能是高置信方向，但平局和客胜合计 46%，说明仍有明显波动空间。

## 场景筛选

`scenario` 不会反向修改主模型。比如“大比分版”只是从完整比分矩阵中筛出总进球大于等于 3 的比分，再重新排序：

```text
scenarioProbability = Σ P(score), where homeGoals + awayGoals >= 3
```

这适合做内容脚本，但不能拿来替代原始胜平负概率。

## 赛后复盘指标

- `hitOutcome`: 胜平负方向是否命中。
- `hitExactScore`: 头号比分是否命中。
- `actualScoreRank`: 实际比分在矩阵里的排名。
- `brierScore`: 胜平负概率校准误差。
- `correctionHints`: 下一版快照应该检查哪些输入。

赛后复盘的重点不是证明某场“应该猜中”，而是判断模型偏差来自基础强度、状态、攻防、临场信息，还是小概率波动。

## 为什么要审计

模型最怕的不是公式复杂度不够，而是输入混乱。例如球队强度来自 6 月 17 日，伤停来自 6 月 16 日，赛程却来自另一版数据。审计脚本会检查版本号、球队数量、强度版本、修正来源，先把脏数据挡在计算前面。

## 方法边界

- 它不能直接捕捉红牌、伤退、临场心态和比赛中战术调整。
- 它不能保证比分，最多给出当前数据快照下的概率分布。
- 它目前重点是 90 分钟赛果；淘汰赛晋级概率必须和 `advanceResult` 分开。
- 它不适合输出下注建议、资金分配或所谓“必中”判断。
