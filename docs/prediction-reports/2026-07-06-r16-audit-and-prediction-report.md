## 5. 对第一版 Skill 的技术审计结论

当前已经可用的地方：

1. `audit -> predict -> scenario -> report` 主链路能跑通。
2. `dataVersion` 由来源版本自动计算，能防止不同批次数据混用。
3. `contextAdjustments` 有来源类型限制，能挡住“AI 直接改胜率”。
4. `90minResult` 和淘汰赛晋级没有混在一起，这一点很重要。
5. 场景筛选只过滤比分矩阵，不反向修改胜平负概率，边界正确。

本轮已修复的问题：

1. 通过 PowerShell 管道生成中文 JSON 时，中文可能被转成 `?`。现在审计器会检查队名、修正标题和事实摘要等关键展示字段；一旦发现连续问号或替换字符，会直接让审计失败。非关键说明字段则保留 warning。
2. 单场报告原本没有自动列出来源版本和事实摘要。现在 `generate-report.mjs` 会从快照里带出 `sourceVersions`、`strengthSnapshotVersion` 和 `officialFacts`。
3. 当前 CLI 原本没有一条命令同时跑多场比赛。现在新增 `predict-batch`，可以按快照批量输出每场预测和 `batch-summary.json`。

仍建议后续增强的地方：

1. `attackStrength`、`defenseStrength`、`formScore` 目前仍是人工复核参数。第一版能用，但后续应沉淀成更明确的换算规则，例如从最近 4 场进失球、对手强度、淘汰赛阶段和伤停影响统一计算。
2. 伤停/停赛现在通过 `contextAdjustments` 表达，能跑通，但建议增加更结构化的 `availability` 字段，区分停赛、伤病、出场成疑、轮换。
3. 批量预测目前输出预测 JSON 和汇总 JSON。后续可以继续扩展为批量生成单场报告、场景筛选和总报告。

## 6. 建议的下一版修正

优先级中：

- 把 `formScore` 和攻防系数从人工值改成可复算规则。
- 增加停赛/伤病结构化字段，减少自然语言修正。
- 增加北京时间和赛事当地时间双时间显示。

优先级低：

- 给 GitHub README 增加一段“如何为真实比赛准备快照”的小教程。
- 增加赛后 `record-result` 的批量复盘入口。
