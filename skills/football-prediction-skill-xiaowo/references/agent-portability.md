# 跨 Agent 可移植执行协议

本协议不依赖某一家 Agent、搜索服务或云平台。宿主只能使用实际存在的能力，并在输出中报告能力检查结果。

## 启动前检查

| 能力 | 检查方式 | 通过条件 | 失败处理 |
| --- | --- | --- | --- |
| 网络能力 | 检查宿主是否提供搜索、网页读取或浏览器工具 | 能访问并记录来源 URL、发布时间与观察时间 | 不搜索、不伪造访问记录；进入缺失资料流程 |
| Node.js | 运行 `node --version` | 主版本不低于 18 | 停止正式流水线，列出未执行命令 |
| PNG 渲染器 | 启动 Playwright Chromium 并读取版本后关闭 | 浏览器成功启动和关闭 | 停止正式报告，不用占位 PNG 降级 |
| 文件写入 | 验证输出父目录可写且目标运行目录不存在 | 可创建新的不可变运行目录 | 更换新目录或请求授权，不覆盖历史运行 |

PNG 渲染器可用以下命令预检：

```bash
node -e "import('playwright').then(async ({chromium}) => { const browser = await chromium.launch({headless:true}); console.log(await browser.version()); await browser.close(); })"
```

## 联网与证据获取

1. 只有在工具列表或宿主说明明确提供网络能力时才执行检索。
2. 每次查询记录查询词、尝试来源、访问结果和时间；“没有结果”与“没有网络能力”必须区分。
3. 优先官方与赛事组织方来源，再使用符合 [evidence-policy.md](evidence-policy.md) 的数据提供方。
4. 付费墙、登录墙、机器人拦截或页面失效都记为失败尝试，不把摘要片段当成已核验事实。
5. 无网络或检索失败时，转入 [missing-data-playbook.md](missing-data-playbook.md)，不得凭模型记忆补写最新事实。

## 工具中立命令约定

- 所有路径都从仓库根目录解析，不依赖当前用户主目录。
- 使用 Node.js ESM 脚本处理 JSON、模型和报告；不要要求宿主安装全局 npm 包。
- 正式输出写入新的 `<out-dir>/<runId>/`，并用进程退出码判断成功或失败。
- stdout 用于简短状态，完整审计写入 JSON 或 Markdown 文件；不得仅在聊天消息中保存关键证据。

## 报告交接

跨 Agent 交接时至少传递：

- `runId`、比赛 ID、固定主客顺序、数据截止时间；
- 赛事画像与基线版本；
- 证据审计状态，以及完整 `missing`、`conflicts`、`rejected`；
- `prediction.json` 和输入哈希；
- `report.md`、`report-long.png`、`render-audit.json` 的路径与 SHA-256；
- 当前步骤、下一步和任何未满足能力。

接收 Agent 必须重新检查文件哈希和渲染审计，不得只相信上一个 Agent 的完成声明。

## 角色边界

- 收集者只记录证据，不预测。
- 审计者只接受、拒绝或隔离证据，不改概率。
- 预测者只读取审计通过的输入，不联网补事实。
- 报告者只解释结构化输出，不手写概率。
- 赛后记录者不改写赛前运行。
- 校准提案必须等待人工审批，不得自动应用。
